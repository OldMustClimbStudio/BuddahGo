# FishyFacepunch tolerates a missing Steam client

A Solo Match must run with Steam closed. Today `FishyFacepunch.Initialize` calls `SteamClient.Init` with no guard (`FishyFacepunch.cs:98-101`), and the call throws `NoSteamClient` when Steam is not running. The exception happens during the TransportManager step of `NetworkManager.InitializeComponents`, so the client, server, scene, observer and prediction managers are never initialized (N3 in `Docs/optimization/p0-validation.md`). `Multipass.Initialize` initializes every child transport, so selecting Yak for solo does not avoid the call.

We patch the plugin's initialization to tolerate the failure. Online entry points then report that Steam is unavailable, while the Solo Match runs on Yak through the same NetworkManager. We chose this over separate NetworkManager setups for solo and online, which would duplicate every scene's network configuration. FishyFacepunch now has its own assembly definition, so the change stays inside that assembly. It is a local change to third-party code and must be kept when the plugin is upgraded.
