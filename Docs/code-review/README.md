## 处理结果

### 1. 模块化、配表、GPU

**发现**：
- `Assets/Scripts` 下 13 个顶层目录里，有 12 个互相依赖，连成一个大循环。只要切断 13 处向上的引用，就能分出 Config、Foundation、Contracts、Rendering、AI 这几个没有循环的层。
- 技能 SO 上约 117 个字段和表格重复，其中 15 个值和表格不一致，比如神足通的冷却在 SO 上是 12/10/10，表里是 5/3/3。
- `SkillExecutor` 在缺表行时，反噬前摇的回退值仍是 1 秒，但表里已经定成 2 秒。
- ModeRule 有 4 列没有任何读取方。
- 游戏专用的编辑器工具分散在两个 Editor 程序集里，测试只能访问其中一个。

**GPU 实测**：
- 静态画面每帧 GPU 约 2.3 ms，平面反射、SSAO、阴影、MSAA 各自的开销都不到 0.15 ms。
- 显卡占用主要取决于帧率：开 VSync 时帧率等于屏幕刷新率。
- 唯一的大头是如来神掌，6 掌齐发时每帧多 3–4 ms。

**改了**：没有动模块和配表，按要求只写方案。GPU 这边只改了一处：墨手流体池在离开比赛场景后释放（`c5f259ad`）。会改变帧节奏或观感的做法都列在 05 §4，等你决定。

**没改**：拆程序集、把数值挪进配表、删 SO 上的重复字段。这些都是大改动，而且几乎所有配表都在 PR #63 的范围里。

## 验证

- **基线**（`aafad1b7`，在编辑器里通过 MCP 跑）：400/400 通过，0 失败。
- **清理后**（HEAD `0ac4e1fe`，同一个编辑器）：206/206 通过，0 失败；编辑器重新编译 0 错误。
- **会进 Play 模式的 3 个用例**（`SoloSessionFlowTests` ×2、`SoloTransportTests` ×1）：两次都没跑出结果。它们进 Play 后会重载域，MCP 就跟丢了测试任务。这 3 个要等编辑器关掉后，用批处理（`-batchmode -nographics -runTests`）补跑。
- **每个提交单独编译**：工作区编译只能代表最终状态，所以另外写了一个编译检查器。它用 `git archive` 取出每个提交的 `Assets/Scripts`、`Assets/Tests`、`Assets/Editor`，再用 dotnet 和 Unity 生成的 csproj 编译 `BuddahGo.Runtime/Editor/Tests` 和 `Assembly-CSharp-Editor`。20 个代码和测试提交逐个检查，全部通过。故意放一个编译错误，检查器能报出来。
- **测试只在最终 HEAD 上跑过**，中间提交没有逐个跑测试。中间提交里的测试代码都编译通过；被删的符号也逐个 grep 过，测试里没有反射引用它们。
- **没有验证的**：
  - 联机双端没有跑，包括掉线解锁和 RPC 编号变化后的双端连接。
  - 构建版没有打包。
  - 墨手流体池释放后再进一局的首掌卡顿没有实测。
- **实测时的副作用**：GPU 测量和 Canvas 验证时进过几次 Play，只改了场景里的对象，渲染器特性在内存里切换后已经恢复，没有保存任何资产。工作区里 `validation.md` 的时间戳改动不是这次提交的内容，没有提交它，也没有还原它。
