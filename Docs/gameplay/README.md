# 玩法深化：技能组合、执念与操作改版

日期 2026-10-25。状态：设计讨论稿，**尚未实现**。“已定”是用户在讨论中确认的规则，“建议”是待用户确认的提案，数值均为暂定、进配表调。现状数值取自 `Assets/Design/Tables/_Export`（dev 5f91e51 之后的配表）。

## 1. 为什么改

按现有代码与配表，玩法深度受这几处限制：

- **同一时间只有一个技能。** 施法锁是全槽共享的，时长约等于效果时长；冷却只比锁多 2 秒（加速 5/3、缓流 8/6、反转 12/10、黑幕 16/14）。三个槽的冷却实际不用管理，也不存在自己技能之间的配合。
- **执念只是惩罚。** 唯一的决策是“现在放还是等 20–30 秒”。六种反噬的代价差别很大（缓流反噬定身 1 秒，反转反噬自反 10 秒），执念价格却几乎相同。
- **搓招和推掌共用 W/↑。** 两只手的冷却是分开的，近身时左右交替推掌（间隔 < 0.35 秒），第三下就凑成 `W↑W` 或 `↑W↑`，误放出槽 0/1 的技能（`ComboSkillInput.FindExactMatchOnSuffix` 按后缀匹配）。
- **瞄准卡手。** 手部朝向靠 ←/→ 以 180°/s 转动，蓄力掌很难打准。

还有几处不在本次范围内，见第 9 节。

## 2. 核心循环

跑线 → 读局势、选组合 → 叠放技能触发 combo → 承担执念风险（反噬 = 10 秒哑火）。

深度从“手指”转移到“决策”：单招输入变简单，复杂度留给“放哪几招、按什么顺序、什么时候兑现”。

## 3. 操作

| 项 | 规则 | 状态 |
|---|---|---|
| 技能释放 | 取消搓招，单键释放 | 已定 |
| 手部朝向 | 鼠标控制；转手有速度上限，鼠标拉动带拖拽感，避免左右晃鼠标时手部抽搐 | 已定 |
| 键位 | 左手 A/D 转向；右手鼠标瞄准，左/右键推掌；Q/E/R（或 1/2/3）放技能 | 建议 |
| 瞄准方式 | 光标投到地面取方向（赛车镜头在动，比鼠标横移更稳） | 建议 |
| 转手上限 | 先沿用 `Push.basic.rotationSpeedDegPerSec` 180°/s，试玩再调；命中率上升后蓄力掌冲量和 buff 时长需要重调 | 建议 |

手部 yaw 已经由客户端同步给服务器（`BuddahHandControl.TrySendYawToServer`），改成鼠标只是换输入来源，不改网络结构。鼠标只适用于 PC，以后支持手柄改用右摇杆。

## 5. 技能组合

### 5.1 二连

| 项 | 规则 | 状态 |
|---|---|---|
| 触发 | 两个技能的效果**同时在身上**就生效，持续到其中一个结束 | 已定 |
| 顺序 | 不看施放顺序，只看效果是否重叠；先开哪个都能触发 | 建议 |
| 判定方式 | 按状态持续判定，不是施法瞬间判定一次；身上状态变化时 combo 跟着变（见下面“随身体状态缩放”） | 建议 |
| 形态 | 强化型：A 改变 B 的参数。合成型：A + B 产生新效果 | 已定 |
| 内容 | 由用户设计 | 已定 |
| 覆盖 | 6 个技能两两组合共 15 对，每套配装正好含 3 对；选技能界面显示本套配装能触发哪些 combo | 建议 |

已定示例：

- **法相金身 + 如来神掌 → 巨掌**（强化型）：神掌按体型等比放大，推力随之变大。这是持续关系：体型变小时，掌和推力也一起变小。
- **神足通 + 禅定缓流 → 冲击波**（合成型）：向周围发射冲击波，让周围的人减速。

注意神足通只有 3 秒。按 1 秒前摇算，含神足通的二连窗口很短；建议把神足通延长到 4–5 秒，或者让它在二连里只当后放的那一招。

### 5.2 三连（建议，待确认）

不建议把三连做成“第三层持续效果”：数值会乘爆（巨大 ×4 再放大冲击波），控制叠到对手没法玩（黑幕 + 反转 + 缓流），场面也读不懂。

建议规则：**前两招成型，第三招收束。**

- 二连生效期间放第三招，会**消耗**两个 buff 剩余的时长，打出一次性的终式；剩余时长越多，终式越强。
- 前两招不分先后，**最后放的那一招决定终式的形态**。同一套配装最多有 3 种终式，取决于哪招最后放。
- 终式 = 二连的**内容** × 第三招的**形态**。只需要设计 15 种二连内容和 6 种形态，不必为 20 套配装各设计一个终式。

| 第三招 | 形态 |
|---|---|
| 神足通 | 冲刺：带着效果向前突进 |
| 禅定缓流 | 场：以自身为中心的范围 |
| 法相金身 | 放大：范围和强度变大 |
| 如来神掌 | 投射：向前打出 |
| 逆姻缘 | 全场：作用于所有对手，强度较弱 |
| 一念光明 | 隐匿：效果对他人不可见 |

示例：

| 三连 | 成型 → 收束 | 终式 |
|---|---|---|
| 金身 + 神掌 + 神足通 | 巨掌 → 冲刺 | 排山倒海：向前冲刺 1–2 秒，沿途撞到的人吃巨掌冲量 |
| 缓流 + 神足通 + 金身 | 冲击波 → 放大 | 震地：一次大范围震波，半径随体型放大（设上限），周围的人减速并被短暂定身 |
| 缓流 + 神掌 + 逆姻缘 | 缚掌（假设的二连）→ 全场 | 千手：全场每个正在减速或反转中的对手各挨一掌，只打一下 |

收束本身也是一个决策：留着 buff 慢慢用，还是现在兑现成爆发。

## 6. 执念与反噬

### 6.1 执念

| 项 | 规则 | 状态 |
|---|---|---|
| 基础曲线 | 不变：每次施法加 `Skill.obsessionGain`（200/300），每秒自然下降 10，反噬概率是 sigmoid（Pmax 95%、k 0.008、中点 500） | 已定 |
| 同招加价 | 同一技能在自己冷却结束后 5 秒内再放，本次执念增量 ×1.15；连续时按复利叠加（×1.15 → ×1.32 → ×1.52）；与中间是否放过别的技能无关 | 已定 |
| 加价层数清零 | 冷却结束超过 5 秒才放就清零；反噬时也清零 | 建议 |
| 落后补偿 | 调大 `catchupRecoveryA`：执念降得越快，放得越多，追赶才真实可感（现在车群内几乎为零） | 建议 |

反噬概率参考：

| 执念 | 0 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 | 1000 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 反噬 % | 1.7 | 3.7 | 7.9 | 16 | 30 | 48 | 66 | 79 | 87 | 91 | 95 |

神足通（增量 300，冷却 5 秒）每次冷却一好就重放：

| 第几次 | 请求时执念 | 反噬 % | 本次增量 |
|---|---|---|---|
| 1 | 0 | 1.7 | 300 |
| 2 | ≈250 | 11 | 345 |
| 3 | ≈545 | 56 | 397 |
| 4 | ≈890 | 91 | 456 |

正常打法最多叠两层；同招加价主要是一个明确的信号，不会让数值失控。

### 6.2 反噬

| 项 | 规则 | 状态 |
|---|---|---|
| 本次技能 | 失效；不加执念，也不计入同招加价的次数 | 已定 |
| 惩罚 | 10 秒内：所有技能锁住；执念条冻结、不自然下降；极速 ×0.85 | 已定 |
| 结束时 | 执念 ×0.8（降低当前持有值的 20%） | 已定（暂定值） |
| 身上已有的 buff | 不打断；已生效的 combo 跟着身体状态继续变化；锁住期间不能放技能，所以无法触发新 combo | 已定 |
| 反作用 | 用户提到反噬“有些许可能出现反作用”。理解为：反噬时，身上已有 buff 有一定概率反转（比如金身变缩小，巨掌跟着变小掌）。统一反噬后金身的缩小变体退役，这是唯一的“变小”来源 | 待确认理解与概率 |
| 六种 `_anti` 变体 | 由统一惩罚取代 | 已定 |

执念条冻结后，解锁时的执念就是反噬时的值 × 0.8：

| 反噬时执念 | 解锁时执念 | 解锁时反噬 % | 降到 300（≈16%）还要等 |
|---|---|---|---|
| 500 | 400 | 30 | 10 秒 |
| 700 | 560 | 59 | 26 秒 |
| 900 | 720 | 81 | 42 秒 |

执念越高时反噬，越吃亏：在 900 反噬，一共约 52 秒放不了安全的技能，差不多半圈。掷骰发生在按键那一刻，玩家看得到概率，所以不是被迫的死循环，但 HUD 必须把当前反噬概率显示清楚。

### 6.3 三连的风险

从执念 0 开始，每招间隔约 1 秒连放三招，三次都不反噬的概率：

| 三招的增量 | 三次反噬 % | 成功率 |
|---|---|---|
| 300 / 300 / 300 | 2 / 16 / 66 | ≈32% |
| 200 / 200 / 300（贵的放最后） | 2 / 8 / 30 | ≈67% |

- 顺序本身就是技巧：便宜的先放，贵的放最后，成功率翻倍。
- 一次三连要用掉约 800 执念，一场约 5 分钟大概只能打 3–4 次，是“大招”的频率。
- 第三招反噬：终式失败，锁 10 秒，但二连 buff 还在。成功率太低的话，可以单独给终式那一招打执念折扣。

## 7. 实现要点

### 7.1 掷骰时机漏洞（必须先堵）

现在是请求时按当前执念掷骰，前摇结束、技能执行时才把增量加进执念（`SkillExecutor.ResolveCastVariant` / `ExecuteQueuedCastAfterDelay`）。去掉全局锁以后，如果 1 秒内连续请求几招，后面几招掷骰时执念还没入账，风险就被绕过了。

解决：采用 4 节的“施法串行”；或者在请求时就把增量预先记入执念。服务器 AI 会检查 `HasPendingCast`（`IsSlotReadyServer`），真人施法路径 `CastSlotServer → TryResolveCast` 是否有同样的检查，实现前要核实。

### 7.2 改动范围

| 改什么 | 原因 |
|---|---|
| `ComboSkillInput`、`Skill/ComboBinding`、`Skill/ComboInput`、HUD 搓招进度 | 改成单键释放后退役 |
| `BuddahHandControl` 输入 | 改读鼠标，加转手速度上限与平滑 |
| 6 个 `Skill_*_Anti` 类、`Skill` 表 `_anti` 行、反噬特效 | 换成统一的反噬效果：减速 + 锁 + 冻结执念 + 结束 ×0.8 |
| `Skill.castLockSeconds` | 去掉，或改成极短的全局间隔；这一步只改配表就能试 |
| `SkillExecutor` | 按槽位记录同招加价层数（可以和现有的 `_nextReadyTime` 放在一起）；反噬改成技能失效、不加执念 |
| `Skill/Obsession` 配表 | 新增列：`repeatWindowSeconds` 5、`repeatGainMultiplier` 1.15、`backfireLockSeconds` 10、`backfireMaxSpeedMultiplier` 0.85、`backfireEndKeepRatio` 0.8 |
| 新增 combo 系统 | 服务器权威的状态重叠判定、二连/终式效果、combo 配表、combo 特效 |
| AI | `AISkillCaster` 不再逐键搓招，直接调用 `CastSlotServer`；人格规格里“技能不会同时生效”“逐键搓招”两条规则作废，要补上 combo 决策；瞄准精度按真人用鼠标的水平重调 |
| HUD | 执念和反噬概率成为主要信息；冷却结束后的 5 秒同招加价窗口要在技能图标上提示 |

## 9. 不在本次范围

- 驾驶仍只有转向：油门恒为 1（`PlayerBuddahInputSource.GetThrottle`），没有刹车或漂移。`space` 已绑定在 Movement 上但代码不读，可以留作以后的驾驶动作。
- 全局技能（逆姻缘、一念光明）对领跑者同样有利。
- 没有防御或反制手段；1 秒前摇的预警目前没有对应的反制机制。
- combo 让控制更容易叠加，受害者保护（控制上限、短暂免控）仍然需要设计。

## 10. 验证顺序

1. **操作**：单键释放 + 鼠标瞄准，单独试玩手感和神掌命中率。不依赖 combo。
2. **节奏与反噬**：去掉全局锁（改配表）、施法串行、统一反噬、同招加价。观察指标：反噬后多久能放出第一招安全技能，超过 30 秒就把 0.8 往下调。
3. **combo**：先做巨掌（强化型）和冲击波（合成型）两个二连，再接一个终式。
