# N8/N9 — remote owner event clocks

P5's initial 36-case matrix found server-authoritative projectile hits whose remote owner impulses remained queued. The client used LocalTick=34560 against canonical event ticks 35280/36696, although its estimated server tick was already 37477. The offset was roughly 50 seconds. Old impulses subsequently contaminated melee positioning. Respawn case 33 also showed server DropRespawn event 35 consumed, while the owner kept consumed=false until a later WrongWayCorrection replaced it.

Impulse queues and wire payloads remain canonical server-stamped. The N8 version tested below used TimeManager.Tick for pure-client consumption. The subsequent `c853768` fix retains that clock for forward simulation but uses historical ServerReplayTick during reconcile/replay; server/host retain the original currentTick. See the [current impulse contract](../prediction-design.md#冲量消费时钟) and [published follow-up evidence](review-runtime-round2.md#r6--r7-and-charged-timing). Teleport queues and their shadow consume local ticks, so only the received client working copy is translated before queueing. Signed wide arithmetic prevents underflow; zero is a valid event tick and bounds saturate. RPC signatures, transport fields, event payload layouts, tick call order, forces and respawn parameters remain unchanged. The results below belong to the N8 version, not the later replay fix.

The initial reproduction is preserved in Logs/p5-physics-matrix and the sibling clone directory. Tools/Validation/owner-event-clock-cases.cs.txt covers eight offset/boundary cases. Focused runtime validation reuses cases 16–35: charged and burst projectiles, both hands' melee/ordinary projectiles, and respawn; both caster owners and 0/100ms latency. It checks new remote-victim event IDs within 0.55 seconds of server consumption, in addition to source coordinates, hits, teleport consumption, R7, replay and room return. Results are below.


## Results

Both editors compiled and passed all eight clock boundary checks. The 20-case run completed at 2026-09-30 07:45:25 UTC with 654/326 host/client heartbeats, zero loc/tel/mod/hof divergence, no registry mismatch, Error or Exception, and successful replay and room return. All eight charged/burst cases matched server/host visual/client visual origin, direction, speed and counts (1/5); all four ordinary projectile cases hit the expected owner. Fresh remote-victim impulse IDs appeared on the owner within at most 0.163s of server sampling. All four respawn cases were routed and consumed; client-owner DropRespawn now completes in both latency modes.

The two latency melee cases still missed because the moving target was outside the hitbox at attack time (case 27 hitbox z≈179 while the victim had advanced well beyond it). They are retained as misses, not relabeled as passes. A separate four-case controlled-range supplement stages both actors through the existing server teleport API at 4.5s and sends the same real left/right-hand keyboard input at 5s. No forces, collider sizes, cooldowns or hit APIs are changed. All four cases produced fresh server victim impulses; the remote owner consumed them within 0.130s. This supplement completed at 07:52:12 UTC with 90/45 zero-divergence heartbeats and no errors. It deliberately stops after the four hit tests; replay/room return is covered by the main run. Logs: Logs/n8-melee-range and the sibling clone directory.

The first supplement attempt aborted before its first case on a shared control-file IOException; switching the harness reader to FileShare.ReadWrite fixed that test coordination issue. Those logs remain under Logs/n8-melee-staged. No production code changed for the supplement.

R7 counters alone did not reveal N8: the old impulse shadow axis was already retired. Acceptance therefore also compares fresh event IDs and timing. These are local Tugboat/ParrelSync checks; external Steam, a Dev Build peer, a driven three-lap race, and general collision-response equivalence remain outside this fixture.
