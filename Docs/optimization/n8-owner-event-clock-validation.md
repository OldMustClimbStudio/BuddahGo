# N8/N9 — remote owner event clocks

P5's initial 36-case matrix found server-authoritative projectile hits whose remote owner impulses remained queued. The client used LocalTick=34560 against canonical event ticks 35280/36696, although its estimated server tick was already 37477. The offset was roughly 50 seconds. Old impulses subsequently contaminated melee positioning. Respawn case 33 also showed server DropRespawn event 35 consumed, while the owner kept consumed=false until a later WrongWayCorrection replaced it.

Impulse queues and wire payloads remain canonical server-stamped. The owner motor now gates their consumption with TimeManager.Tick; server behavior still uses the original currentTick. Teleport queues and their shadow consume local ticks, so only the received client working copy is translated before queueing. Signed wide arithmetic prevents underflow; zero is a valid event tick and bounds saturate. RPC signatures, transport fields, event payload layouts, tick call order, forces and respawn parameters remain unchanged.

The initial reproduction is preserved in Logs/p5-physics-matrix and the sibling clone directory. Tools/Validation/owner-event-clock-cases.cs.txt covers eight offset/boundary cases. Focused runtime validation reuses cases 16–35: charged and burst projectiles, both hands' melee/ordinary projectiles, and respawn; both caster owners and 0/100ms latency. It checks new remote-victim event IDs within 0.55 seconds of server consumption, in addition to source coordinates, hits, teleport consumption, R7, replay and room return. Results pending.
