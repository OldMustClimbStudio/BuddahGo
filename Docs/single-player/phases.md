### S1 本地流程与表现验收

以下是待核对的验收要求，不代表已完成。把现有流程的 owner/caller 与 Solo 路径对应，再由主 S1 任务在真实本地运行中检查；代码存在、场景绑定有效、合成 Finish 或单张截图均不足以证明流畅。

| 交接/表现 | 必须观察的本地行为 | 证据边界 |
|---|---|---|
| 加载与场景 handoff | 设置→选择→比赛加载、玩家生成/就绪、画面淡入淡出及控制器启停衔接；无重复对象、卡加载或短暂错误控制 | 记录各阶段状态与实际转换，不能只凭最终场景名 |

| 倒计时→GO→驾驶 | 倒计时与权威 GO、运动解锁一致；姿态/相机及输入控制权交接流畅，无多帧冻结、突然纠正或残留输入锁 | 真实输入与运动反馈，结合 handoff 状态/时间定位；流畅性不由静态检查或无 Error 日志代替 |
| 比赛→结算 | 自然完赛、结算演出/镜头、Practice 计时展示与按钮激活衔接正确 | 区分 Race End、ResultInteractive 和 UI 实际可操作，避免过早终止观察 |
| Rematch / 返回 / Esc | 重开重新经过加载与开场；返回或退出恢复可用主菜单，网络/输入/计时/镜头状态清理且能再进入 | 反复走实际流程；一次合成重开不等于 V8/V11 完成 |

**涉及模块**：`ForwardSimPlanner`（完整版）、`AIDifficultyProfile`（三档）、Fumble、走线偏移、追赶、遮挡视野时的精度下降、`AITuningHarness`。

**完成标准**
1. 三档快捷难度/精准度调节及其速度、跟随/转向精度、反应参数拟在 `AIDifficultyProfile` 中分别可调，不写死；Fumble 单列，不以故意卡住或失控降难度。映射和参数待实测，方案见 ai-testing.md。
2. **调参场景**：
   - 可以指定 AI 数量、难度和旋钮值，让 AI 自动跑 N 圈。
   - 输出计划/实际完成圈数、每圈用时、完成率、撞墙次数、平均偏离和每 tick 的规划耗时；记录带时间/圈号/赛段的位置轨迹，逐圈叠图并标注碰撞、复位、卡住和技能事件。
   - 每组配置先记录无技能基础驾驶，再手动或按脚本施加单项技能干扰：推挤、减速、加速等；单项结果可解释后再测组合。临时调高 Fumble 的调参运行单列，不与正常配置混算。
3. 三档难度的实测指标写入 progress.md：每圈用时、撞墙/圈、平均横向偏离、AI 之间的横向离散度、超车次数、`AI.Plan` 耗时。三档之间的指标要有可区分的差异；普通难度无障碍无技能每圈约 90–120 秒为调校目标；成功率和圈速波动用于诊断改善，不作为机械通过门槛。
4. 5 个 AI 同场时，横向离散度不低于约定阈值（在调参时确定并记录）；被推、被遮挡后，都能在约定时间内回到走线。

**验证**：V6、V7、V9、V10、V11、V12。

## S5 AI 施法规则

**目标**：AI 在合适的时机施放技能，让单机对局有派对式的互相干扰。

**完成标准**
1. 在 A3 中每个 AI 独立评估技能机会，可在现有 `IAISkillRule` 接口中使用简单概率规则，不要求复杂行为树；各自维护目标、冷却/决策状态和可复现随机流，不用共享单一决策让五车同步施法。概率值未定，仍遵守合法目标、冷却、执念值、反噬与现有施法入口，规则逻辑有 EditMode 测试。
2. 调参场景可以单独开关 AI 施法，并统计各技能的施放次数和反噬次数。
3. 用不同合法技能配置验证“具备条件 → 选择目标/时机 → 请求施放 → 实际效果”的完整链路，同时记录无条件时是否错误施放；再看五 AI 比赛中的恢复、轨迹与完赛。玩家开赛后不操作不等于暂停或豁免其角色，也不授权修改比赛结束规则。区分 AI 自然完赛、规则结算前未完赛、故障与证据不足，矩阵见 ai-testing.md。
4. A3 通过后进入 A4：通知用户手动试玩完整流程并记录反馈；自动化结果不能代替用户试玩结论。

**验证**：V5、V6、V10、V11、V12。
