## 1. 流程（五步，全组共用）

用户 2026-10-28 给出的工业化流程，本项目按以下方式落地：

| 步骤 | 一般做法 | 本项目 |
|---|---|---|
| 1 | 主美对齐参考图与关键词 | 由 [调研文档](vfx-design-research.md) 与参考板承担，关键词与方向见第 2 节；用户签字 |
| 2 | 做 5–10 个标杆特效当全组的尺子 | 六个技能的正常 + 反噬共 12 个特效就是标杆集；如来神掌是第一把尺子 |
| 3 | 写参数表和命名规范 | 第 5 节参数三层与 VFX 表、第 6 节命名 |
| 4 | 搭共用的贴图、材质、模板 | 第 7 节 shader 族、贴图库、模板 prefab，随如来神掌一起建起来 |
| 5 | 新特效从模板起步，每个都过评审 | 每个技能先填拆解表、用户纸面确认一次，出三张材质小样确认一次（2026-10-28 评审后加的唯一中间评审），再一口气做完全部阶段、反噬与档位，整体给用户看一次（用户 2026-10-28：不分多次原型评审） |

本轮分工：由 Claude 通过 Unity MCP 与编辑器脚本搭建资产和 shader，用户只做看图 / 试玩验收（用户自述手调效果一般）。本分支的文档会话只写文档，不改代码或资产。

## 2. 视觉方向（已定）

- **地图基调**：枯山水、禅院、谧静；日落下的大理石与沙地，ACES + 轻 bloom。技能特效允许比场景大胆、更有冲击力，但不是另一种美术。
- **方向：国风水墨 + 金为基调，借鎏金佛光的形体；分层照《绝区零》仪玄：实体是光，水墨在外层。** 第二次画面评审（2026-10-28 晚，用户："水墨感来自于一些外层的特效，但是不应该是实体"）后定为：
  - **实体（主体）= 自发光的金色能量体**：HDR 自发光走场景 bloom，软边，带流动的丝状高光；明度**外亮内暗**（轮廓与指尖最亮，掌心压到暗金，前导边缘最亮），不是金属 matcap，也不是深色剪影。实体永远发光，画面里"黑"从来不是实体。
  - **水墨 = 外层**：只在飞行拖尾、出掌劲风、消散、施法确认爆发这四类外层里，做半透明的烟墨与大笔触，并带金火星和金边；只在实体外、永远在运动、不贴地、不贴实体表面（规则见第 7 节材质定义）。印记用朱砂印章。
  - 金粒子两种：贴实体飞出的碎羽 / 流线，和散在墨里的点火星；它们是实体与墨之间的过渡层。
  - 只借卡通方向的一条时序规则：接近白的亮度只在释放那 2–4 帧出现。
- **已废弃的两版**（留作教训，不再回头）：第一版"半透明网格 + Fresnel 墨线 + 滚动噪声墨晕"读成污斑；第二版"深色剪影 + 金 matcap + 粒子皮、墨只做实心硬边形"读成黑手。两版的共同错误是把墨放在了实体上。
- **色板（全技能共用）**：实体暗金 `#8A5A14`（掌心）→ 实体金 `#F2C14E`（轮廓）→ 暖白 `#FFF3C4`（前导边缘与闪光帧）；金粒 `#F2C14E` → 琥珀 `#C8842A`；外层墨 `#15151A`；玄 `#2A2F3A`（烟云底）；宣纸灰 `#4A4642`；朱砂 `#C0392B`（仅印记）。每个技能一个主色、一个母题、一个剪影；禁止多层火焰烟雾堆叠。
- **反噬色板**：去掉全部金色：实体的发光色换成绛紫 `#5B2A6E` / 暗红 `#7A1F1F`，金火星换成暗红火星，外层墨不变，朱砂印记换成灰白"破印"。全技能的反噬都按"去金换紫红"执行，不另做造型。
- 关键词：光（实体）、墨（外层）、金火星、一笔、印、经文、莲座、光轮、克制的余韵。
- 禁止：深色或半透明的实体、墨贴在实体表面或混进金里、贴地的墨、静止的墨、半透明灰 / 棕褐的中间调、滚动噪声的污斑、程序化伪字、放射状多条笔触、所有层同时同亮度出现。

## 3. 分层概念（采用用户提供的《游戏特效分层拆解规范》）

### 3.1 视觉层级

| 层级 | 作用 | 注意力占比（经验值） | 画质优先级 |
|---|---|---|---|
| Core 核心层 | "这是什么技能"：轮廓与主色 | ~60% | 1，任何档位保留 |
| Secondary 次级层 | 体积、动势、环境反馈 | ~30% | 2，Medium 以上保留 |
| Accent 点缀层 | 精致度与节奏感 | ~10% | 3，仅 High |

先做 Core 并确认能单独读懂，再加 Secondary，最后加 Accent。层次看结果不看组件数量：一个粒子系统如果已经分出层次，不必拆成多个。

### 3.2 功能层

glow 辉光（Add）、flash 闪光（Add，1–3 帧）、distortion 扭曲（屏幕扭曲，首版不做）、smoke 烟雾 / 笔触（外层墨，Alpha，核心不透明只羽化边缘）、sparks 火花 / 碎点（金粒：碎羽 / 流线与火星，Add）、decal 贴花（Alpha，淡出要慢）、mesh 网格主体（自发光能量体，外亮内暗 + 前导边缘 + 溶解，本项目新增）、light 实时光（本项目新增，见第 8 节）。一个元素 = 一个视觉层级 + 一个功能层。

### 3.3 时间阶段

| 代码 | 阶段 | 目的 | 时长参考 |
|---|---|---|---|
| `Buf` | 状态持续（本项目新增） | 告诉对手"这个人现在有 X 状态"，权重必须低于任何一次释放 | = 技能 buff 时长 |
| `Chg` | 蓄力 / 预备 | 预告、吸引视线、指明方向 | = 技能蓄力时长 |
| `Prj` | 飞行 / 持续 | "这是什么、往哪飞、有多大、来自谁" | = 投射物寿命或效果时长 |
| `Imp` | 释放 / 命中 | 最强反馈，峰值集中在前 2–4 帧 | 0.05–0.2 s |
| `Dis` | 消散 | 能量衰减，画面让回给比赛 | 0.3–0.8 s |
| `Lin` | 残留 | 环境痕迹、余韵 | ≤ 1.5 s（本项目上限，见第 8 节） |

节奏：蓄力慢、释放快、消散中、残留短。每个技能至少覆盖三个阶段。

### 3.4 拆解表模板

| 元素 | 层级 | 功能 | 阶段 | 起止(s) | 颜色 | 混合 | 优先级 | 备注 |
|---|---|---|---|---|---|---|---|---|
| | Core / Secondary / Accent | glow / flash / distortion / smoke / sparks / decal / mesh / light | Buf / Chg / Prj / Imp / Dis / Lin | 相对阶段起点 | 主色 #RRGGBB | Emissive / Cutout / Add / Alpha / Distort / Decal | 1–3 | 降级策略、玩法信息、参考 |

起止时间写成"相对该阶段起点的秒数"，而阶段的绝对起点来自玩法数值（第 5 节），这样改玩法时长不用改表。携带玩法信息的元素（主体、前导、方向提示）在备注里标 **玩法信息**，任何档位和任何距离都不省略。

## 4. 运行时结构（设计，待实现）

- **阶段控制器**：一个全技能共用的运行时组件（建议名 `SkillVfxPhaseController`），挂在特效 prefab 根上。技能代码只在正确时机报告阶段事件（Buf 开始 / Chg 开始并持续给进度 / Imp / Prj 开始 / Dis / 命中 / Buf 结束）并传入玩法数值；控制器按阶段启停各层、按 VFX 表缩放时长、按档位与距离省略层。每层在 prefab 上标注自己的阶段、层级、优先级。现状对比：`ChargedHandProjectileRuntime` 自己 `SetFloat("Progress")`、自己实例化发射特效、自己算寿命，每个技能一套私有逻辑。
- **特效只在表现层**：现状已经是服务器只跑不可见碰撞体、视觉由 ObserversRpc 让客户端本地实例化，不走 NetworkObject；保持不变。`vfx_quality` 与未来的"特效质量"档位都是客户端本地的，携带玩法信息的层不依赖它们。
- **技能资产统一引用 vfx_id**：现状加速、缓流走 `SkillVfxDatabase` 的 vfx_id，如来神掌直接引用两个 prefab，巨大化与反转的 vfx_id（`accel_anti_vfx`、`reverse_turn_trap_vfx`、`reverse_turn_trap_anti_vfx`）没有条目。改为所有技能只写 vfx_id，VFX 表登记 id 到 prefab 的映射与视觉数值，预热列表从表生成，悬空 id 清掉。
- **反噬配对**：反噬特效与正常特效在表里显式配对（`<id>_anti` 命名，并有一列 `anti_of`），共用同一套层结构，只换反噬色板。
- **视觉尺寸跟随玩法尺寸**：主体网格的外接盒按碰撞盒尺寸自动缩放，随 `PlayerScaleEffect`（巨大化 / 缩小）一起缩；拖尾长度按速度 × 寿命推导。用户以后改数值不用再手调特效。
- **自动校验**（配表导入规则 + EditMode 测试）：每个技能引用的 vfx_id 必须有条目；特效总时长不得超过施法锁；拆解表声明的阶段在 prefab 上都有对应层；新 shader 登记进 `Assets/VFX/PreloadShader.shadervariants`，新 prefab 进预热列表。

## 5. 参数三层与 VFX 表

| 层 | 内容 | 存放 |
|---|---|---|
| 玩法数值 | 蓄力时长、投射物寿命、buff 时长、碰撞盒尺寸、发射数量与间距、速度 | 已有的技能配表（`Assets/Design/Tables/Skill/Skill.xlsx`）。特效不另存一份，运行时直接推导 |
| 视觉专属数值 | 各层相对时长比例、尺寸倍率、强度、拖尾长度系数、消散时长、点光寿命、远距省略阈值 | 新的 VFX 表（配表清单早已建议的 `VFX_Table`，按 [design-tables/README.md](../design-tables/README.md) 的规则建表） |
| 颜色、贴图、曲线、材质 | | prefab 与材质，不进表 |

VFX 表建议列：`vfx_id`、`anti_of`、`prefab_path`、`chg_ratio`（蓄力层占蓄力时长的比例）、`imp_frames`、`dis_seconds`、`lin_seconds`、`buf_fade_seconds`、`trail_seconds`（拖尾长度 = 速度 × 该值）、`scale_multiplier`、`light_seconds`、`light_intensity`、`far_threshold_m`（远距省略阈值）、`post_pulse_seconds`、`warmup`。时序初始值（用户 2026-10-28 确认，之后随时改）：预备 = 蓄力时长；释放闪光 2–4 帧；飞行 = 投射物寿命；未命中到期的消散 0.3–0.5 s；命中后的消散 ≤ 1.5 s；buff 状态标识淡入淡出各 0.3 s；施法者本地后期脉冲 ≤ 0.15 s。

## 6. 命名

- 元素 / 发射器：`FX_<技能>_<阶段>_<层级>_<功能>_<序号>`，阶段用 `Buf / Chg / Prj / Imp / Dis / Lin`，层级用 `C / S / A`。例：`FX_Palm_Imp_C_Flash_01`、`FX_Palm_Prj_S_Smoke_01`。
- 技能短名：`Palm`（如来神掌）、`Accel`（神足通）、`Slow`（禅定缓流）、`Curtain`（一念光明）、`Giant`（巨大化）、`Reverse`（转向反转）；反噬加 `Anti`：`FX_PalmAnti_Imp_C_Flash_01`。
- 贴图 `T_FX_<描述>_<类型>`（类型：Mask / Noise / Flow / Flipbook / Glyph / Packed）；材质 `Mat_FX_<技能>_<元素>`；shader `FX/<功能层>`；prefab `VFX_<技能>`、`VFX_<技能>_Anti`；vfx_id 小写蛇形 `palm`、`palm_anti`。
- 资产目录：`Assets/VFX/<技能中文名>/` 沿用现有目录；共用资源放 `Assets/VFX/Shared/`（贴图、材质、模板 prefab），shader 放 `Assets/Rendering/Shaders/FX/`（与已有的 `BuddahGo/Lit` 同处）。

## 7. Shader、贴图与模板

- **路线**：Shuriken 粒子系统 + 手写 HLSL shader + 网格主体为默认；Shader Graph 退出特效制作（用户用过，效果一般；文本 shader 便于生成、修改、review 与 diff）；主体是自发光网格，不需要粒子皮（第二次评审取消了"点云网格粒子皮"：实体是光，贴在发光体上的点看不出来）；金粒用 Shuriken 的拉伸粒子与点火星。不用 VFX Graph：项目里没有可复用的 VFX Graph 资产，代码新建要走 VFX 包内部 API，脆弱，且所有层都不到万级粒子。NOVA Shader（MIT）只作参考读，不引入插件目录；它的通道打包与顶点流约定可以照搬。
- **shader 族**（按功能层拆，参数覆盖大部分需求）：`FX/Additive_Glow`、`FX/Alpha_Smoke`、`FX/Decal`、`FX/Mesh_Energy`（网格主体：自发光能量体——外亮内暗的明度遮罩（按到轮廓的距离或法线与视线夹角，掌心暗金、轮廓金）、流动的丝状高光贴图、沿飞行方向的前导边缘遮罩抬到暖白、整体自发光脉冲、溶解；不用 matcap、不用深色底、不用 Fresnel 墨线与顶点抖动）、`FX/Distortion`（首版不做，预留）。`FX/Alpha_Smoke` 要支持"核心不透明 + 边缘羽化"的外层墨与朝运动方向一侧的金边。共同能力：噪声扰动、极坐标、溶解 / 侵蚀、软粒子、Custom Vertex Streams（Custom1.x = 进度、.y = 溶解、.z = 随机相位、.w = 预留）。
- **材质定义（2026-10-28 评审新增）**：
  - 实体金 = HDR 自发光：掌心暗金 `#8A5A14` → 轮廓金 `#F2C14E`（强度约 1.5–2.5）→ 前导边缘与闪帧暖白 `#FFF3C4`；bloom 由场景后期提供，不单独加辉光面片。不用 matcap、不用平涂、不混任何墨。
  - 外层墨 = `#15151A` 的烟墨与大笔触，Alpha 混合，笔触核心不透明度 ≥ 0.85、只羽化边缘（≤ 宽度的 15%）；四条硬规则：只在实体外（外圈、后方、拖尾）、永远在运动、单片寿命 ≤ 0.4 s、每片墨里必带金火星。第五条针对本项目的亮沙地：每片墨朝飞行 / 运动方向的一侧带一条细的金色发光边（金边墨），否则远处的墨和地面分不开。
  - 金粒 = Add 混合的碎羽 / 流线（有方向、沿运动拉伸）与点火星；颜色 `#F2C14E` → `#C8842A`。
  - 亮度顺序：闪帧 > 前导边缘 > 实体轮廓 > 金粒 > 实体掌心 > 墨。面积越大的层越透明越暗，面积越小的层越亮；任何时刻最亮的是金或暖白，最大的是墨但它最透。
- **贴图**：形状类贴图必须是手绘质量的素材，不能用程序化生成（评审结论：线噪声"笔触"、Voronoi "墨晕"、伪字"经文"是脏乱的直接来源）。笔触用公共领域 / CC0 的真实毛笔扫描，或 Claude 图像生成初稿再清理成硬边 mask / SDF；经文用真实《心经》文本，以 OFL 授权的 Noto Serif CJK 烘成贴图，字必须可辨；掌印从佛手网格正投影取形后清理边缘。程序化只用于噪声、溶解、渐变与通道打包。火焰 / 烟 / 碎屑可复用已购的 Piloto Studio、GabrielAguiar 贴图（只用贴图，不用它们的 prefab）；用户有更好素材随时替换。
- **水墨可行性（2026-10-28 查 GitHub 的结论）**：实时的湿墨晕染只存在于二维画布模拟（[Aureliaar/sumi](https://github.com/Aureliaar/sumi) 的 WebGL 乒乓纹理湿纸模拟、[komietty/unity-moxi-ink](https://github.com/komietty/unity-moxi-ink) 的格子 Boltzmann 墨模拟、lywedo/Unity-Effect 的 compute 扩散）或整屏后期（[keijiro/KinoAqua](https://github.com/keijiro/KinoAqua) 水彩，作者自述未优化到可实用），没有一个能装进"单个投射物 ≤ 0.3 ms"的预算，也没有现成的 Unity 开源技能特效级水墨实现。大神与 [mixandjam/Okami-Celestial-Brush](https://github.com/mixandjam/Okami-Celestial-Brush)（MIT）式的游戏水墨，本质都是实心纯黑形 + 预先画好的笔触贴图；RealTimeVFX 上的 Unity 墨笔刷教程也是用 After Effects 手工做的墨烟贴图，不是 shader 里算出来的。所以本项目不做湿墨晕染；第二次评审后"墨"定义为外层的烟墨与大笔触（手绘质量的烟与笔触贴图，Alpha 混合），正是"游戏里的水墨"这一类做法。
- **模板 prefab**：`Assets/VFX/Shared/VFX_Template.prefab`，带阶段控制器与六个阶段的空槽、命名好的占位元素；新特效从它起步。
- **贴花层**：平面面片 + `FX/Decal`（深度偏移、沿地面摆放），不改渲染器；赛道基本是平面，出现确实需要贴合曲面的技能再评估 URP Decal Renderer Feature（渲染器改动受 [rendering/racemap/README.md](../rendering/racemap/README.md) 的登记规则约束）。
- **屏幕后期层**：施法者本地的后期脉冲（bloom 抬升、短暂色差、相机冲击）用已有的 Feel（`SkillFeelRouter`，`Skill_Reflection_Local` 那一套）按技能事件 id 配置；世界内特效与 Feel 完全解耦；只对施法者和（以后）受害者触发，旁观者不触发。现有的施法者 FOV 推近保留现状不动。

## 8. 预算与档位

平台只有 PC Steam。每个技能的硬预算（High Fidelity，1080p）：

| 项 | 上限 |
|---|---|
| 单次施放全部特效 GPU | ≤ 0.3 ms |
| 同屏 6 个参赛者同时施放 | ≤ 1.5 ms |
| 每次施放实例化的粒子系统 | ≤ 4 个 |
| 总粒子 | ≤ 2000 |
| 主体网格 | ≤ 3000 三角面 |
| 实时光 | 每次释放一个寿命 ≤ 0.5 s 的点光（不投阴影），蓄力期间一个低强度点光；Low 档全关 |
| 阴影 | 特效不投不接 |
| 残留层 | ≤ 1.5 s，纯视觉，不参与玩法 |

档位：现有 `vfx_quality` 三档（Low / Medium / High，钩子 `VfxQuality.Current` 已存在，无读者）对应优先级：Low 只留优先级 1 且发射量 40%，Medium 留 1–2 且 70%，High 全量。用户计划之后另开一档"特效质量"，越低省略越多层，规则相同。**距离分级**：离相机远于 `far_threshold_m` 的别人的特效自动省略 Accent、点光、贴花，只保留携带玩法信息的主体与拖尾；本地玩家自己的永远全量。阈值与档位联动，开"特效质量"档时一并实现。

验证方法：编辑器内用现有的 `RaceMapRenderCost` 一类测量（同机同会话对比），Rendering Debugger 看 overdraw；数字写进各技能文档。

## 9. 验收与交付

每个技能一次纸面确认（拆解表 + 方向），一次基准小样，然后做完全部阶段、反噬与档位省略，整体给用户看一次：Practice 模式施放正常与反噬各 3 次，录短视频或固定视角连拍（沿用渲染文档的 JPEG 对比做法），用户在 Editor 里看过后回"过 / 改哪一层"。交付清单：

- [ ] 拆解表（第 3.4 节模板）
- [ ] 特效资产 + 预览视频（含慢放）
- [ ] 各档位截图（优先级 1 / 2 / 3 分别验证）
- [ ] 性能数据：粒子数、overdraw、draw call、GPU 时间
- [ ] 命名符合第 6 节，无未用资源；废弃资产按 [CONTRIBUTING.md](../../CONTRIBUTING.md) 的运行时引用检查后删除

**基准小样（2026-10-28 第二次评审定，取代"材质小样"）**：全量搭建前，先在调试场里按仪玄的分层搭一个"仪玄式基准"并在**我们的亮赛道**（沙地 + 蓝天）前截三张静帧给用户看，只验材质与分层，不验时序：(1) 一只发光金佛手飞行，侧 45°，身后拖墨烟尾 + 金火星；(2) 出掌瞬间，暖白闪帧 + 墨色劲风向后甩 + 朱砂印记；(3) 蓄力中，半大的发光手 + 脚下一圈金色经文环。基准必须在亮场景里测（仪玄的场景偏暗，金天然最亮；我们要测的正是墨在亮沙前会不会变灰）。用户回"过 / 改哪层"后再做完全部阶段。小样里实体任何一处读成黑或灰、或者墨贴在实体上，就算不过。

本轮不做受击反馈（用户 2026-10-28：先优化特效本身），命中层在拆解表里只作占位；音频项目里完全没有，本轮只预留事件钩子。

## 12. 术语

- **分层表 / 拆解表（Layer Sheet）**：第 3.4 节的表，每个技能必填，验收按它逐层对照。
- **阶段控制器（Phase Controller）**：第 4 节的共用运行时组件。
- **标杆特效（Benchmark Effect）**：12 个技能特效，作为全组的尺子。
- **玩法信息层**：携带"是什么、往哪、多大、来自谁"的元素，任何档位与距离都不省略。
- **反噬色板**：去金换紫红的替换规则。
- **实体（Body）**：技能的主体，自发光的金色能量体；永远发光，永远不是黑。
- **外层墨（Outer Ink）**：只在实体外、运动中的烟墨与大笔触，带金火星和金边；本项目里"水墨感"只由它承担。
- **金粒（Gold Motes）**：碎羽 / 流线与火星，实体与墨之间的过渡层。
- **基准小样（Baseline Stills）**：第 9 节的三张"仪玄式基准"静帧，全量搭建前的唯一中间评审。
- **粒子皮 / 实心墨形**：第二次评审前的两个已废弃概念，见 [push-projectile-hands.md 第 13 节](push-projectile-hands.md#13-2026-10-28-第二次评审实体与外层水墨分家)。
