# 如来神掌（push_projectile_hands）特效重做

通用规范、色板、命名与预算见 [README.md](README.md)；候选方向与参考见 [vfx-design-research.md](vfx-design-research.md)。本文记录 2026-10-28 与用户探讨的结论：现状问题、目标、分层拆解表、反噬变体、档位、验收标准与待办。本文是设计，不代表已实现；实施后在"验收记录"补结果。

## 1. 玩法事实（特效必须服从，数值由配表管，本轮不改）

技能资产 `Assets/Skills_Assets/Skills/Skill_PushProjectileHands.asset`（配置仓库优先于资产）：

| 项 | 值 | 对特效的意义 |
|---|---|---|
| 冷却 / 施法锁 | 18 / 15 s | 特效总时长不得超过施法锁 |
| buff 时长 | 15 s | `Buf` 阶段长度；期间每次推掌变成蓄力掌 |
| 蓄力 `buildUpSeconds` | 1 s | `Chg` 阶段长度；`ChargedHandProjectileRuntime` 把 `Progress` 在前 80% 推到 1，发射时置 1 |
| 动作延迟 `delayedPushActionSeconds` | 0.9 s | 手部动画延迟，与蓄力并行 |
| 蓄力掌冷却 | 1 s | 两掌之间最短间隔 |
| 速度 / 寿命 / 冲量 | 600 / 3 s / 500 | `Prj` 阶段 3 s；拖尾长度按速度推导 |
| 碰撞盒 | 60 × 90 × 20，出手点高 30 | 主体网格外接盒贴合它，前缘对齐 |
| 施法者 FOV | +30，1 s 升、整段 buff、1 s 回落 | 保留现状不动 |
| 反噬 | 立即向后扇形 5 掌，间距 30，前移 100、高 30，蓄力 0.3 s，寿命 2 s，命中附加旋转冲量 50 | 见第 5 节 |

联机：服务器只跑不可见碰撞对象，视觉由 ObserversRpc 让每个客户端本地实例化；特效纯表现层，保持不变。

## 2. 现状与问题

资产（全部来自 2026-03-23 的一次提交，之后未动）：

| 资产 | 内容 | 问题 |
|---|---|---|
| `如来神掌VFXGraph.prefab` → `如来神掌.vfx` | VFX Graph，容量 30000 粒子，暴露 `TargetPos` / `Progress` / `SpawnParticles`；粒子按 `佛手Projectile.fbx` 烘出的点云（三份 pcache，1 万与 3 万点，共 3.3 MB）聚成金色的手；反噬一次开 5 个实例 | 只有一层；粒子聚形僵硬，远看糊成一团读不出手形；3 万粒子 × 5 实例的开销换不来剪影 |
| `射击特效.prefab` | 8 个 Piloto Studio 粒子系统堆叠（光圈、火焰、横向眩光、烟、碎屑等），根发射器循环 5 s，一个槽引用已丢失的材质 `b739a3f…`（已确认不渲染） | 像枪口焰，和"佛掌"主题不搭；颜色（金 + 蓝火 + 橙烟）杂乱；循环根发射器靠脚本按最长寿命销毁 |
| 飞行中 | 只有 VFX Graph 实例随碰撞体移动 | 没有拖尾、没有前导、没有体积，3 s 里像一团光点飘过 |
| 命中 / 到期 | 无任何特效，到期瞬间消失 | 没有反馈、没有消散 |
| buff 期间 | 只有施法者本地 FOV 推近 | 对手看不出谁有掌形 buff |
| Feel | 该技能事件 id 为空，只有 Buddah 上通用的 `Skill_Reflection_*` 闪光 | 无本技能的屏幕层 |
| 预热 | `VfxStartupWarmup` 列表未含本系列 | 首次施放可能卡顿 |
| 废弃 | `HandProjectile.prefab` 与它独占的 `如来神掌.prefab`（16 个 Piloto 粒子系统）无任何引用，Buddah 的 `projectilePrefab` 槽为空 | 混淆"到底哪个在用" |

用户 2026-10-28 的判断：以上基本都难看，FOV 推近本身还好；根本原因是单层、没有分层设计。

## 3. 目标

- 方向：水墨 + 金为基调，借鎏金佛光的形体（[README.md 第 2 节](README.md#2-视觉方向已定)）。签名剪影是**一只掌心朝前、五指微张的佛手**（飞行时正面就是掌心，受害者看到的就是"一只手拍过来"），出掌瞬间叠一枚朱砂**掌印**。
- 受害者要在命中前 ≥ 0.5 s 看见掌飞来，先看见金色前导边缘再看见墨。
- 主体是网格而不是粒子聚形；每一层各司其职；时间轴有预备、释放、飞行、消散。
- 不改任何玩法数值；视觉贴数值。

## 4. 分层拆解表（正常版本）

阶段起点由玩法数值决定：`Buf` 起点 = 施法确认；每次推掌为一个 `Chg` 起点（t = 0），`Imp` 在 t = 蓄力时长（现 1.0 s），`Prj` 从 `Imp` 到 t = 蓄力 + 寿命（现 4.0 s），`Dis` 从到期或命中开始。表内起止是相对各阶段起点的秒数；写成"×蓄力"或"×寿命"的按比例随配表变化。

### 4.1 `Buf` 状态层（施法者身上，15 s）

| 元素 | 层级 | 功能 | 阶段 | 起止(s) | 颜色 | 混合 | 优先级 | 备注 |
|---|---|---|---|---|---|---|---|---|
| 掌心光轮：施法者胸前一圈缓慢旋转的细金环 | Secondary | glow | Buf | 0.0 – buff 结束，淡入淡出各 0.3 | 金 `#D8B25A`，低亮度 | Add | 2 | 告诉对手"这个人每一掌都是蓄力掌"；权重低于任何一次出掌；远距省略 |
| 施法确认爆发：一圈墨晕 + 金边自胸前扩开 | Secondary | smoke | Buf | 0.0 – 0.4 | 墨 `#0B0B0D` → 透明，金边 | Alpha | 2 | 与现有 `Skill_Reflection_Shared` 闪光对齐时机 |

### 4.2 `Chg` 蓄力（每掌，1 s）

| 元素 | 层级 | 功能 | 阶段 | 起止(s) | 颜色 | 混合 | 优先级 | 备注 |

| 脚下墨迹晕开：施法者脚下一片随 flow map 扩散的墨迹 | Secondary | decal | Chg | 0.0 – 1.0×蓄力，之后 0.3 淡出 | 墨 `#0B0B0D` 60% 不透明 | Alpha | 2 | 跟随施法者位置，不随旋转；远距省略 |
| 金篆经文环：墨迹上沿极坐标浮现一圈金色经文 | Accent | glow | Chg | 0.2 – 1.0×蓄力 | 金 `#D8B25A` | Add | 3 | 极坐标 UV 旋转一张经文条贴图（`T_FX_Sutra_Glyph`） |

### 4.3 `Imp` 出掌（t = 蓄力时长，2–4 帧为峰）

|---|---|---|---|---|---|---|---|---|

|---|---|---|---|---|---|---|---|---|

### 4.6 `Imp`（命中）与 `Lin`：本轮占位

用户 2026-10-28 决定先优化特效本身，受击反馈后续再做。阶段控制器预留命中事件；拆解表预留：命中闪光（Core / flash，1 帧亮金）、受害者身上指向推飞方向的墨色劲风（Secondary / smoke）、受害者处的朱砂掌印（Secondary / decal，`Lin` ≤ 1.5 s）、受害者本地屏幕反馈（Feel）。本轮都不实现。

### 4.7 `Buf` 结束

掌心光轮 0.3 s 淡出；若 buff 结束时仍有掌在飞，飞行层不受影响。

## 5. 反噬变体（`push_projectile_hands_anti`，vfx_id `palm_anti`，`anti_of = palm`）

同一套层结构，按"去金换紫红"的反噬色板，并按掌数共享预算：

- `Chg`（0.3 s）：一片脚下墨迹（共享一份）；五只小手（主体缩放 0.6）在后方扇形位置同时显形，墨线 + 绛紫 `#5B2A6E` 填；经文环、墨尘、点光省略。
- `Imp`：一枚灰白"破印"闪光（共享一份，`T_FX_PalmPrint_Broken_Mask`），一道向前（发射反方向）的墨色劲风（共享一份），一个点光（共享一份）。
- `Prj`（2 s）：每掌只有主体 + 短拖尾（`trail_seconds` 减半）+ 暗红 `#7A1F1F` 前导边；碎屑省略。五掌的饱和度略低于正常版本：更弱的要看起来更弱。
- `Dis`：主体溶解同正常版本。
- 施法者本地后期脉冲用现有的 `Anti_Reflection_Local` 色调（偏冷 / 暗）。

## 6. 档位与距离

| 档位 | 保留 |
|---|---|
| High | 全部 |
| Medium | 优先级 1–2：主体、前导、闪光、拖尾、劲风、墨迹贴花、朱砂印记、光轮、后期脉冲；发射量 70% |
| Low | 优先级 1：主体、前导、闪光、主体溶解；发射量 40%；点光全关 |

远于 `far_threshold_m` 的别人的掌：省略经文环、墨尘、墨滴、点光、墨迹贴花与印记，保留主体、前导、拖尾、闪光。本地玩家自己的永远全量。

## 8. 资产与实施清单（供实施会话，本文档会话不改代码）

1. 共用基础设施（随本技能建立）：`FX/Additive_Glow`、`FX/Alpha_Smoke`、`FX/Decal`、`FX/Mesh_Energy` 四个 shader；`Assets/VFX/Shared/` 下的噪声打包图、笔触贴图、模板 prefab；阶段控制器；VFX 表与 vfx_id 统一；导入规则与 EditMode 测试。
2. 主体网格：在 Unity 里确认 `Assets/Sources/Buddah/佛手Projectile.fbx`（1.7 MB）的面数与手势；手势合适则减面到 ≤ 3000 三角面复用，不合适则新建低模，手势取"掌心朝前、五指微张"。
3. 贴图初稿：`T_FX_PalmPrint_Mask`、`T_FX_PalmPrint_Broken_Mask`、`T_FX_Sutra_Glyph`、`T_FX_Brush_Stroke`（飞白笔触）、`T_FX_Ink_Flow`（flow map）；由 Claude 用图像生成工具出初稿，用户可替换。
4. prefab：`VFX_Palm`、`VFX_Palm_Anti`，从模板起步，元素按第 4、5 节命名（`FX_Palm_Chg_C_Mesh_01` 等）。
5. 登记：新 shader 进 `Assets/VFX/PreloadShader.shadervariants`，prefab 进预热列表；Feel 事件 id `palm_launch_local`、`palm_anti_launch_local` 进 `SkillFeelRouter`。
6. 验收通过后退休：`HandProjectile.prefab`、`如来神掌.prefab`、三份 `pca_HandProjectile*.pcache`、`如来神掌.vfx` 与 `如来神掌VFXGraph.prefab`、`射击特效.prefab`。删除前按 [CONTRIBUTING.md](../../CONTRIBUTING.md) 确认运行时加载引用；Piloto、GabrielAguiar 插件目录本轮不碰。

## 9. 验收标准

一次纸面确认（本文档）后做完全部阶段、反噬与档位省略，整体给用户看一次：

- Practice 模式施放正常与反噬各 3 次，录短视频或固定视角连拍（含慢放）；各档位截图；性能数据填入第 7 节。
- 逐层对照第 4、5 节的拆解表：每个优先级 1 的元素都在、都可单独读懂；受害者视角能在命中前 ≥ 0.5 s 看见金色前导；整个技能里只有出掌那 2–4 帧接近白。
- 改配表里的蓄力时长、寿命、碰撞盒后，特效自动跟随，不需手调。
- 用户回"过 / 改哪一层"。
