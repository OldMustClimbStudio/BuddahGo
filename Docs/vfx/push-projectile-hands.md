通用规范、色板、命名与预算见 [README.md](README.md)；候选方向与参考见 [vfx-design-research.md](vfx-design-research.md)。本文记录 2026-10-28 与用户探讨的结论：现状问题、目标、分层拆解表、反噬变体、档位、验收标准与待办。同日第一次画面评审后修订了第 1、3、4、5、7、8、9 节，诊断、修正决定与水墨可行性调研见第 12 节。本文是设计，不代表已实现；实施记录见 [push-projectile-hands-implementation.md](push-projectile-hands-implementation.md)，实施后在"验收记录"补结果。

## 3. 目标

- 方向：水墨 + 金为基调，借鎏金佛光的形体（[README.md 第 2 节](README.md#2-视觉方向已定)）。签名剪影是**一只掌心朝前、五指微张的佛手**（飞行时正面就是掌心，受害者看到的就是"一只手拍过来"），出掌瞬间叠一枚朱砂**掌印**。
- 受害者要在命中前 ≥ 0.5 s 看见掌飞来，先看见金色前导边缘再看见墨。
- 主体 = **不透明的深色网格剪影**（承担形状、方向、大小）+ **致密的金色软粒子皮**（承担质感，VFX Graph，观感参考 keijiro/SplatVFX）。网格不再做半透明、Fresnel 墨线与顶点抖动；粒子不再是"聚成手形"的点云，而是贴在剪影上的皮（2026-10-28 评审改动，理由见第 12 节）。
- "墨"只做实心硬边的形：一笔式笔触、刻印、剪影；不做晕染。材质小样仍显脏就去墨只留黑金。
- 每一层各司其职；时间轴有预备、释放、飞行、消散；各层按亮度顺序先后出现，不同时同亮。
- 不改任何玩法数值；视觉贴数值。

## 4. 分层拆解表（正常版本）

阶段起点由玩法数值决定：`Buf` 起点 = 施法确认；每次推掌为一个 `Chg` 起点（t = 0），`Imp` 在 t = 蓄力时长（现 1.0 s），`Prj` 从 `Imp` 到 t = 蓄力 + 寿命（现 4.0 s），`Dis` 从到期或命中开始。表内起止是相对各阶段起点的秒数；写成"×蓄力"或"×寿命"的按比例随配表变化。

|---|---|---|---|---|---|---|---|---|
| 掌心光轮：施法者胸前一圈缓慢旋转的细金环 | Secondary | glow | Buf | 0.0 – buff 结束，淡入淡出各 0.3 | 金 `#D8B25A`，低亮度 | Add | 2 | 告诉对手"这个人每一掌都是蓄力掌"；权重低于任何一次出掌；远距省略 |

### 4.6 `Imp`（命中）与 `Lin`：本轮占位

用户 2026-10-28 决定先优化特效本身，受击反馈后续再做。阶段控制器预留命中事件；拆解表预留：命中闪光（Core / flash，1 帧亮金）、受害者身上指向推飞方向的墨色劲风（Secondary / smoke）、受害者处的朱砂掌印（Secondary / decal，`Lin` ≤ 1.5 s）、受害者本地屏幕反馈（Feel）。本轮都不实现。

### 4.7 `Buf` 结束

掌心光轮 0.3 s 淡出；若 buff 结束时仍有掌在飞，飞行层不受影响。

## 5. 反噬变体（`push_projectile_hands_anti`，vfx_id `palm_anti`，`anti_of = palm`）

同一套层结构，按"去金换紫红"的反噬色板，并按掌数共享预算。五掌按第 1 节的实际布局：一字横排、在施法者前方生成、向后飞穿过施法者；共享元素只放在 0 号掌上并移到横排中心。

- `Chg`（0.3 s）：一笔脚下墨圆（共享一份）；五只小手（等比装进 60 × 50 × 20 碰撞盒，约 0.56 倍）横排同时显形，深色剪影 + 绛紫 `#5B2A6E` matcap，粒子皮用绛紫、密度减半（五掌合计 ≤ 15000 GPU 粒子）；经文环、聚拢金点、蓄力点光省略。
- `Imp`：一枚灰白"破印"（共享一份，`T_FX_PalmPrint_Broken_Mask`，印章式硬边、带裂口），主体自发光脉冲用灰白而不是亮金；一道向前（发射反方向）的单笔劲风（共享一份）；一个点光（共享一份）。
- `Prj`（2 s）：每掌只有主体 + 粒子皮 + 短拖尾（`trail_seconds` 减半）+ 暗红 `#7A1F1F` 前导边；碎屑省略。五掌的饱和度略低于正常版本：更弱的要看起来更弱。五只半透明紫手并排会读成"一排牙齿"（评审截图），所以反噬的剪影必须同样不透明。
- `Dis`：主体溶解同正常版本。
- 施法者本地后期脉冲用现有的 `Anti_Reflection_Local` 色调（偏冷 / 暗）。

## 6. 档位与距离

| 档位 | 保留 |
|---|---|
| High | 全部 |
| Medium | 优先级 1–2：主体、粒子皮、前导、闪光、拖尾、劲风、墨圆贴花、朱砂印记、光轮、后期脉冲；发射量 70% |
| Low | 优先级 1：主体、粒子皮（密度 40%）、前导、闪光、主体溶解；Shuriken 发射量 40%；点光全关 |

远于 `far_threshold_m` 的别人的掌：省略经文环、聚拢金点、金点碎屑、点光、墨圆贴花与印记，保留主体、粒子皮（密度减半）、前导、拖尾、闪光。本地玩家自己的永远全量。

## 8. 资产与实施清单（供实施会话，本文档会话不改代码）

1. 共用基础设施（随本技能建立）：`FX/Additive_Glow`、`FX/Alpha_Smoke`、`FX/Decal`、`FX/Mesh_Energy` 四个 shader；`Assets/VFX/Shared/` 下的噪声打包图、笔触贴图、模板 prefab；阶段控制器；VFX 表与 vfx_id 统一；导入规则与 EditMode 测试。
2. 主体网格：在 Unity 里确认 `Assets/Sources/Buddah/佛手Projectile.fbx`（1.7 MB）的面数与手势；手势合适则减面到 ≤ 3000 三角面复用，不合适则新建低模，手势取"掌心朝前、五指微张"。
3. 贴图（2026-10-28 评审后改为手绘质量素材，程序化只留噪声 / 溶解）：`T_FX_PalmPrint_Mask`、`T_FX_PalmPrint_Broken_Mask`（从佛手正投影取形后清理成硬边 mask）、`T_FX_Sutra_Glyph`（真实《心经》文本，Noto Serif CJK，OFL，烘成环形条）、`T_FX_Brush_Stroke`（公共领域 / CC0 的真实毛笔单笔扫描，或图像生成初稿清理成 mask）、`T_FX_Gold_Matcap`（金属 matcap）；删除 `T_FX_Ink_Flow`（不再有流动墨晕）。用户可替换。
4. 粒子皮：VFX Graph 资产 `VFX_Palm_Skin.vfx`，输入主体网格（表面 + 体积采样）、进度、溶解、颜色；按 README 第 7 节不另写 shader。
5. 材质小样（README 第 9 节）：三张静帧交用户，回"过 / 去墨 / 改"后再做全部阶段。
6. prefab：`VFX_Palm`、`VFX_Palm_Anti`、`VFX_Palm_Buf`（buff 状态层挂在施法者身上，实施会话补的命名），从模板起步，元素按第 4、5 节命名（`FX_Palm_Chg_C_Mesh_01` 等）。
7. 登记：新 shader 进 `Assets/VFX/PreloadShader.shadervariants`，prefab 进预热列表；Feel 事件 id `palm_launch_local`、`palm_anti_launch_local` 进 `SkillFeelRouter`。
8. 验收通过后退休：`HandProjectile.prefab`、`如来神掌.prefab`、三份 `pca_HandProjectile*.pcache`、`如来神掌.vfx` 与 `如来神掌VFXGraph.prefab`、`射击特效.prefab`。删除前按 [CONTRIBUTING.md](../../CONTRIBUTING.md) 确认运行时加载引用；Piloto、GabrielAguiar 插件目录本轮不碰。

## 9. 验收标准

一次纸面确认（本文档）、一次材质小样（三张静帧，README 第 9 节）后做完全部阶段、反噬与档位省略，整体给用户看一次：

- Practice 模式施放正常与反噬各 3 次，录短视频或固定视角连拍（含慢放）；各档位截图；性能数据填入第 7 节。
- 逐层对照第 4、5 节的拆解表：每个优先级 1 的元素都在、都可单独读懂；受害者视角能在命中前 ≥ 0.5 s 看见金色前导；整个技能里只有出掌那 2–4 帧接近白。
- 任何一帧截图里没有半透明灰 / 棕褐的中间调、没有滚动噪声的污斑、没有读不出的伪字；蓄力中的手不遮住施法者；最亮的元素是金而不是白色面片。
- 改配表里的蓄力时长、寿命、碰撞盒后，特效自动跟随，不需手调。
- 用户回"过 / 改哪一层"。

## 12. 2026-10-28 第一次画面评审：诊断与修正

实施会话按第 4、5 节搭完第一版后（截图在共享笔记 `palm-vfx-shots/`，不进仓库），用户的评价："画风不仅脏、乱，而且真的不好看，整体都是一坨的感觉，没有赏心悦目的风格"；墨层"很脏乱、没有具体的表现感觉"；并给了 keijiro/SplatVFX 与 keijiro/DkvfxSketches 作为想要的观感。本节把截图、贴图、shader 与参考板并排对比的结论、用户的修正答复和水墨可行性调研记下来；上面各节已按结论改写。

### 12.1 诊断：结构对，质感错

分层、阶段、命名、配表、控制器都按设计落了地，脏乱全部来自材质与贴图这一层。按对画面的伤害排序：

| # | 画面上的现象 | 原因（已核对实现） | 对应修正 |
|---|---|---|---|
| 1 | 手是半透明的，边缘一圈深色"墨线"在掠射角鼓成一圈，整只手像隔着脏玻璃 | `FX/Mesh_Energy` 用 Alpha 混合、填充不透明度 0.85，视角 Fresnel 做墨线，再叠顶点抖动 | 网格改不透明剪影；删 Fresnel、抖动（第 4.4 节） |
| 2 | 手上棕褐色污斑在动 | "墨晕"= 一张程序化 Voronoi 噪声在表面滚动，0.45 的暗化叠在平涂金上 | 删滚动墨晕；金改 matcap 金属质感（README 第 7 节材质定义） |
| 3 | 出掌时最亮的东西是一只错位的白色剪纸手 | 掌印闪光是朝向相机的白色手形面片，贴图是程序化"团块手"，与主体不对齐 | 闪光改为主体自发光脉冲，删白色面片（第 4.3 节） |
| 4 | 劲风像撕裂的胶片 / 放射状黑条 | 7 颗拉伸粒子各贴一张"线噪声"笔触贴图，两层反向滚动 | 改为一笔真实毛笔扫描的实心笔触（第 4.3 节） |
| 5 | 脚下一块灰色污渍 | 墨迹贴花 60% 不透明 + flow map 扩散，边缘全是半透明灰 | 改为硬边一笔墨圆，小样仍脏则删（第 4.2 节） |
| 6 | 经文环是一圈细碎的乱码 | `T_FX_Sutra_Glyph` 是程序化的"篆意"笔画，不是字 | 改为真实《心经》文本烘图（第 4.2 节） |
| 7 | 蓄力 0.5 s 时手已经遮住半个屏幕，施法者被罩住 | 蓄力缩放 0.6 → 1.0，而掌本身是 60 × 90 的巨掌 | 蓄力缩放 0.25 → 0.5，出掌瞬间跳到 1.0（第 4.2 节） |
| 8 | 金色发闷、偏土黄，墨偏灰 | Alpha 混合的半透明层叠在暖色赛道上：金被背景冲淡，墨被抬成灰 | 所有墨改 Opaque / Cutout；金用 matcap（README 第 7 节） |
| 9 | 所有层同时亮起、亮度相近，没有主次 | 各层起止几乎重叠，又都是半透明 | 亮度顺序与先后出现写进 README 第 7 节与第 3 节目标 |
| 10 | 贴图整体是"程序化的样子" | 笔触 = 横向线噪声、经文 = 伪字、掌印 = 团块、噪声 = 彩色 Voronoi，全部由编辑器脚本生成（实施会话为避开授权问题放弃了图像生成初稿） | 形状类贴图改手绘质量素材，程序化只留噪声 / 溶解（第 8 节第 3 项） |
| 11 | 稀疏的半透明墨滴读作灰尘 | 墨尘、墨滴、余墨都是 Alpha 的黑点，与 keijiro 参考里"上千个软点聚成体积"正相反 | 墨点改金点并入粒子皮；主体加致密粒子皮（第 4.2、4.4、4.5 节） |
| 12 | 反噬五只紫色透明小手并排像一排牙齿 | 同 1，再乘五 | 反噬剪影同样不透明（第 5 节） |
| 13 | 指尖附近有来源不明的红色杂点；蓄力填充有一条硬的水平线 | 实施会话自查发现，来源未定 | 实施时清掉；小样截图里不得再出现 |

与参考的差距一句话：大神、奇谭过场、燕云墨扇的"墨"都是实心纯黑的形，边缘要么硬、要么是真实毛笔的飞白；keijiro 两个仓库的质感来自致密的软点体积。第一版两样都没有：墨是半透明灰噪声，粒子是稀疏黑点。

### 12.2 修正决定（用户 2026-10-28 答复）

| # | 问题 | 决定 |
|---|---|---|
| Q1 | keijiro 参考意味着什么 | 网格只做不透明深色剪影（形状、方向、大小），质感来自贴在网格表面与内部的致密金色软粒子皮（VFX Graph）。"主体是网格"改为"主体 = 剪影网格 + 粒子皮" |
| Q2 | 墨怎么做 | **用户：墨很难做，目前效果非常一般；查 GitHub 有没有可参考的，没有就不要强行尝试。** 调研结论见 12.3：墨只做实心硬边的形 + 手绘贴图，不做晕染；材质小样仍脏就去墨只留黑金 |
| Q3 | 贴图来源 | 手绘质量素材：真实毛笔扫描（公共领域 / CC0）或图像生成初稿清理成 mask；经文用真实《心经》文本 + Noto Serif CJK（OFL） |
| Q4 | 蓄力时的手多大 | 0.25 → 0.5，出掌瞬间到 1.0 |
| Q5 | Fresnel 墨线 | 删除；深色实心底 + 金 matcap 的对比代替，可选 1 px 轮廓 |
| Q6 | 劲风与拖尾 | 一笔或两笔大的真实笔触形，≤ 0.3 s；不放射状多条、不滚动 |
| Q7 | 出掌闪光 | 主体自发光脉冲 2–4 帧 + 单独的朱砂印记；删白色手形面片 |
| Q8 | 评审节奏 | 全量搭建前加一次"材质小样"（三张静帧），之后仍是一次整体验收 |
| Q9 | 脚下墨迹 | 硬边一笔墨圆（ensō）；小样仍脏则删 |

Q1、Q3–Q9 按推荐；Q2 用户另有判断，按 12.3 收窄。

### 12.3 水墨可行性调研（GitHub，2026-10-28）

找到的实时水墨实现分三类，没有一类适合"单个投射物 ≤ 0.3 ms、每场 6 人同屏"的技能特效：

| 类 | 仓库 | 做法 | 结论 |
|---|---|---|---|
| 二维画布湿墨模拟 | [Aureliaar/sumi](https://github.com/Aureliaar/sumi)（MIT，WebGL 2） | 乒乓半精度纹理模拟湿纸：水按纸纤维渗透、颜料随水走、边缘先干所以边缘更深；干笔用一张 320 × 2048 的扫描干刷图做阈值 | 效果最接近真水墨，但是整张画布的多 pass 模拟，不能挂在一只飞行的手上 |
| 二维格子 Boltzmann 墨模拟 | [komietty/unity-moxi-ink](https://github.com/komietty/unity-moxi-ink)（MIT）、lywedo/Unity-Effect 的 `ChineseInkPainting`（compute） | MoXi 论文的流体模拟 | 同上，画布级，且无性能数据 |
| 整屏水彩后期 | [keijiro/KinoAqua](https://github.com/keijiro/KinoAqua)（Unlicense，Unity 2022.3+） | flockaroo 的 Shadertoy 水彩滤镜移植 | 作者自述"未优化到可实用"；是整屏风格化，不是技能层 |
| 游戏里的"水墨" | [mixandjam/Okami-Celestial-Brush](https://github.com/mixandjam/Okami-Celestial-Brush)（MIT）；RealTimeVFX 的 Unity Ink Brush 教程 | 实心纯黑的形 + 预先画好的笔触 / 墨烟贴图（教程里的墨烟是 After Effects 手工做的） | **这才是可用的路线**：质量全在贴图与形，shader 里只有 cutout、溶解、流动 |
| 3D 水墨着色 | [sacshadow/3D_ChineseInkPaintingStyleShader](https://github.com/sacshadow/3D_ChineseInkPaintingStyleShader)（MIT）、boringsky/Unity_ChinesePainting | 场景级的 NPR 着色（README 没有技术说明） | 面向整个场景的风格化，不是单个特效 |

所以：本项目的"墨"收窄为实心硬边的形（剪影、一笔、刻印）加手绘质量的笔触贴图；湿墨晕染、滚动噪声"墨晕"与半透明墨一律不做。墨保留与否由材质小样决定，去墨只留黑金（深色剪影 + 金粒子皮 + 朱砂印记）是兜底，不再另找方案。

### 12.4 材质小样

按 README 第 9 节：三张静帧（飞行侧 45°、出掌瞬间、蓄力中），只验材质与形。通过标准：没有半透明灰 / 棕褐中间调，最亮的是金，墨是实心的，字可辨，手不遮施法者。用户回"过 / 去墨 / 改哪层"后再做完全部阶段、反噬与档位。
